Featured Project

Evently — Event Ticketing Platform

  • Full-stack ticketing platform: organizers create tiered events, attendees buy tickets, and staff validate entry by QR code at the door.
  • The purchase path locks the tier row before the capacity check, so concurrent buyers serialize per tier while different tiers sell in parallel. A committed k6 run of 200 concurrent buyers against 50 seats settles at exactly 50 sales and 150 clean rejections.
  • An Idempotency-Key header maps a retry back to the original ticket, so a client that times out and retries can never buy twice.
  • Authentication built from scratch — Ed25519-signed access tokens, rotating refresh tokens with reuse detection, Argon2id hashing, and per-IP rate limiting.

Featured Project

mini-sql — SQLite-Style Engine

  • A database engine built one layer at a time in C: REPL → statement parser → executor → cursor → pager → disk.
  • Row layout is computed at runtime from a schema rather than frozen into a compile-time struct — the decision that keeps CREATE TABLE and multiple tables reachable without a rewrite.
  • Rows serialize into 4 KiB pages cached by a pager and flushed to a backing file, so data survives across runs. Reads and writes go through a cursor abstraction — the seam the B-tree slots into next.

Engineering Practice

  • Correctness first

    Failure, concurrency, and validation are handled explicitly — record-level locks in the banking server, three validation layers in the pipeline framework, nine ordered safety gates before any automated remediation runs.

  • Test what matters

    Unit and integration tests where they earn their keep: 44 tests over the KV store's data structures and wire format, 54 covering pipeline action validation, 40 test modules including chaos and end-to-end runs on the DevOps platform.

  • Understand before abstracting

    I build the lower-level implementation first — a hash table, an event loop, a wire protocol, a lock discipline — so I know how the abstraction behaves when it breaks.

  • Document decisions

    Architecture, trade-offs, and failure modes go in the repository — the KV store ships a design document covering its concurrency model, wire format, and rehashing strategy alongside the code.

  • Automate feedback

    CI catches what review misses. The KV store builds across two operating systems, two compilers, and two build types on every push, with dedicated AddressSanitizer, UndefinedBehaviorSanitizer, and ThreadSanitizer jobs.
