A note on the work

I'm drawn to the layers most engineers abstract over. The places where a node can crash mid-write, two clients can commit at the same instant, and the network can silently drop half the traffic — and the system still has to be correct.

So I build small, deliberate systems from scratch. A Redis-style key-value store. A Raft-based consensus engine. A write-ahead log. An LSM-tree. Each one is an excuse to study the same trade-off in a different shape — durability against latency, consistency against availability, simplicity against speed.

My depth lives in POSIX systems programming, write-ahead logging, LSM-tree storage, and distributed consensus. I'm looking for backend, platform, or infrastructure roles where reliability and failure-aware design aren't an afterthought.
