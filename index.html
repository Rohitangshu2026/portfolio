About

I'm interested in software systems where correctness, reliability, and performance matter.

I build backend and systems software from first principles — concurrent network services, storage engines, data pipelines, and production-style APIs. My work spans POSIX systems programming, TCP/IP, concurrency, Spring Boot, MySQL, Docker, and Kubernetes, alongside coursework in distributed computing, cloud computing, and software architecture.

I particularly enjoy understanding what happens underneath the abstractions: how data survives failure, how concurrent operations remain consistent, how services behave under partial failure, and how systems recover safely. Most of my projects are deliberately built without frameworks in the way, so the failure modes are mine to handle.

Engineering Practice

  • Correctness first

    Failure, concurrency, and validation are handled explicitly — record-level locks in the banking server, three validation layers in the pipeline framework, nine ordered safety gates before any automated remediation runs.

  • Test what matters

    Unit and integration tests where they earn their keep: 44 tests over the KV store's data structures and wire format, 54 covering pipeline action validation, 40 test modules including chaos and end-to-end runs on the DevOps platform.

  • Understand before abstracting

    I build the lower-level implementation first — a hash table, an event loop, a wire protocol, a lock discipline — so I know how the abstraction behaves when it breaks.

  • Document decisions

    Architecture, trade-offs, and failure modes go in the repository — the KV store ships a design document covering its concurrency model, wire format, and rehashing strategy alongside the code.

  • Automate feedback

    CI catches what review misses. The KV store builds across two operating systems, two compilers, and two build types on every push, with dedicated AddressSanitizer, UndefinedBehaviorSanitizer, and ThreadSanitizer jobs.
